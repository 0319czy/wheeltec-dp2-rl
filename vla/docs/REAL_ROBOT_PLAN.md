# 实机部署方案（分阶段，先仿真后实车）

> 状态：拟稿（2026-11-22）。实机部分依赖「USB 摄像头采购」与「固件打补丁并烧写」，尚未执行。
> 相关：`specs/VLA-TASK-SPEC.md`、`deploy/firmware-notes.md`、`deploy/PROTOCOL.md`。

## 1. 目标架构

```
笔记本（RTX 5060，本机）
  相机 ──► VLA(SmolVLM-256M + 动作头) ──10 Hz──► (v, ω)
  语音 ──► faster-whisper ──► 指令文本 ──┘
                                          │ 串口（USB CDC / 蓝牙串口，ASCII 帧）
                                          ▼
                         STM32F103 固件（100 Hz 平衡/速度环，LQR/APP 固件）
```

- VLA 不在车上跑：STM32 只有 72 MHz/20 KB RAM 量级，跑不了视觉模型；
- 10 Hz 的速度指令由车上 100 Hz 闭环执行，平衡、限幅、看门狗都在固件里；
- 这是 VLA 在低算力小车上的标准分层做法，也是简历里「VLA 指令执行」的真实含义。

## 3. 固件补丁（LQR/APP 固件，DP2_RTOS）

见 `deploy/firmware-notes.md` 与（待建）`deploy/firmware-patch/`：

- 协议帧：`#V<v_mm_s>,<w_mrad_s>;`（如 `#V250,0;` = 0.25 m/s 直行；`#V0,1000;` = 原地左旋 1.0 rad/s）；
- 解析位置：`HAREWARE/usart3.c` 的 `DP2_Param_Feed()` 加分支（复用现有 `#name=value;` 缓冲与看门狗时间戳）；
- 消费位置：`MiniBalance/control.c` 的 `Normal()`：每 10 ms 把 (v, ω) 换成目标轮角增量
  `Δθ_L = (v − ω·b)·dt/r`、`Δθ_R = (v + ω·b)·dt/r`，`b=0.095 m`、`r=0.0335 m`（宏定义，待实测标定）；
- 安全：沿用 300 ms 看门狗（超时清零目标）、限幅（|v|≤0.35 m/s、|ω|≤1.0 rad/s）、保留原有 APP 单字符遥控作为回退；
- 上车前先在 PC 上用 `test_parse_vw.c` 单测解析与量纲。

## 4. 上位机桥

`deploy/bridge.py`（mock 已跑通）：

- 相机采集 → 图像（与训练一致的预处理：裁剪/缩放到 128 或其整数倍，RGB）；
- 语音/文本 → 指令（`deploy/asr/normalize.py` 的 12 条归一化）；
- VLA 推理 10 Hz → (v, ω) → ASCII 帧 → 串口；
- 遥测回读：`{A...}$` 帧解析速度/角度/电压，网页或终端显示；
- 安全：串口默认拒绝真车（`--allow-real` + `DP2_ALLOW_REAL=1` 双重开关）、失联 0.3 s 停车、急停键。

## 4.5 部署干跑（不碰车，先验证整条链路）

`bash scripts/deploy_dryrun.sh 0 runs/bc_v6b_lowlr/best.pt 10`（2026-11-23 实测通过）：

```
[asr] ... wav 识别："去找红桶。"（297 ms，backend=small_gpu）
[bridge] camera=video policy=vla link=mock proto=vw rate=10.0 Hz
[bridge] 指令：id= 8 靠近红桶（归一化 score=0.95）
[  2.60s] v=+0.009 w=+0.020 frame='#V9,20;'   A(7,11 mm/s, ...)
[bridge] 结束：37 帧 / 4.03 s = 9.18 Hz；act_ms ≈ 16 ms
```

- 2026-11-23 修了一处：`deploy/bridge.py` 原先只在**非 mock** 时才打开真实相机，导致无车联调永远用合成图；现在 `--camera N` 一律用真实相机（打不开才回退合成图并告警）。
- 用笔记本自带相机做干跑时，画面是真实房间（不在训练分布内），VLA 输出接近 0 —— 这属于预期，干跑只验证「相机采集 → VLA 10 Hz → ASCII 帧 → 串口层」的链路与延迟，不代表实机成功率。
- 车端 `/dev/ttyACM0`（QinHeng USB Single Serial）已出现；**是否打开/烧写要用户确认**（打开串口可能触发 DTR 复位）。

## 4.6 相机选型、FOV 标定与安装（2026-11-24 新增）

**买什么**：UVC 免驱 USB 相机，1080p（`MJPG` 30 fps 可用），水平 FOV **100°–120°**（广角），
镜头可手动调焦/固定焦距（避免自动对焦抖动），线长 ≥1 m，价格 50–120 元即可。
到货后先跑 `scripts/check_camera.py`（本轮新增，已用笔记本自带相机验证：640×480、27.2 fps、读帧 p50 31 ms、缩放 128 p50 1.1 ms、亮度 128.8）：

```bash
.venv/bin/python scripts/check_camera.py                 # 打开/帧率/画质/VLA 输入样张
# FOV 标定：A4 纸(210 mm)竖放、距镜头 1 m，量出像素宽后回填
.venv/bin/python scripts/check_camera.py --obj-width-mm 210 --obj-dist-mm 1000 --obj-px 320
```
判据：水平 FOV 85°–130°（最佳 90°–120°）；帧率 ≥15 fps；亮度 mean 80–170。

**装在哪**：车体前部上方，镜头离地 **15–20 cm**，光轴**下俯 10°–20°**，前方不遮挡（留出 ±60° 视场）。
安装面优先级：顶板前缘 > 侧板加 L 支架 > 车头横梁。常用做法（都不需要改车体）：
1. **3D 打印 L 形支架**：底板 50×40×4 mm（4×M3 沉头孔，孔距按你量到的顶板螺孔），竖板高 40–60 mm，相机座面下俯 15°，M2.5 螺丝固定模块；
2. **亚克力 L 板**（2 mm）+ 双面胶/热熔胶，打孔位置同上；
3. **临时验证**：扎带 + 泡棉双面胶（先跑通再换正式支架）。

**装好后的三条验证**（对应验收）：
1. `check_camera.py` 的 128×128 样张构图与 sim 渲染图相近（能看到前方 ~60° 内的桶）；
2. `bash scripts/deploy_dryrun.sh <cam> runs/bc_v6b_lowlr/best.pt 10` 跑 10 s，act_ms 稳定 <50 ms、输出帧率 ≈10 Hz；
3. 把车放在仿真同样的场景（红/蓝/绿桶，间距 1.2 m）拍照，肉眼对比「桶在画面里的比例」——偏大说明俯角/焦段不对，需重装。

> **关于 `三维模型/二阶平衡小车（客户图）.stp`（2026-11-24 实测解析）**：ZW3D 导出的 54 MB STEP、86.8 万个实体、238 个实体（solid）。
> 按实体逐个算包围盒后确认：**它是「控制板装配」而不是整车**——主体是一块 **85.0 × 56.0 × 1.6 mm 的 PCB**
> （另有 28×28×3 的风扇、21.25×7.64×9.9 的四个小件等），最大的两个实体是图纸框/构造几何（82 m / 0.5 m 级假尺寸），
> 所以**拿不到车体顶板的安装孔位**。相机支架因此建议走「免打孔」路线：
> ① 3D 打印 **夹持式卡扣**（夹在车体顶板前缘，厚度按卡尺实测 3–5 mm 设计）；
> ② 亚克力 L 板 + 3M 双面胶/热熔胶（临时验证最快）；
> ③ 若车体有现成螺孔，用卡尺量两孔中心距后把参数填进支架模型即可。
>
> 复现方法（工具已入库）：`.venv/bin/python scripts/inspect_step.py <模型.stp> --plates`，
> 输出各实体包围盒与"1.4–1.8 mm 厚板"清单，本次结果：PCB `84.98 × 55.97 × 1.60 mm`、面积 4757 mm²。

## 5. 实机验收（建议标准）

1. 静态：相机装车 → 采集 1 帧与仿真构图对比（目标桶在画面中的位置/大小相近）；
2. 单指令：`保持站立`、`向前走`、`原地左旋` 各 3 次，肉眼与遥测确认方向正确、无摔倒；
3. 视觉闭环：`靠近红桶`、`靠近蓝桶` 各 5 次，成功 ≥ 3 次（d<0.5 m 视为到达）；
4. 视频：录 3 段（站直/靠近红桶/原地旋转），存 `media/real_*.mp4`；
5. 数据回填：实机采集 50–100 条成功演示，作为微调数据（跨域 gap 收敛）。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 实拍视角与仿真差异大（摆杆入镜、光圈/白平衡不同） | 相机前置避开摆杆；训练时加亮度/对比度/噪声随机化；实机 50–100 条微调 |
| 底层速度跟踪与仿真不同（轮胎打滑、地面材质） | 先用简单指令验收；必要时标定 b、r 与 v 增益 |
| 串口丢帧/延迟 | ASCII 帧带校验与序号，超时保持上一帧 0.1 s 后归零 |
| 车上固件版本与预期不符 | 先烧官方 LQR 固件确认；补丁只加不改，保留回退 bin |
| 语音识别错误 | 归一化 + 二次确认（识别文本显示在界面上，用户可重说） |
